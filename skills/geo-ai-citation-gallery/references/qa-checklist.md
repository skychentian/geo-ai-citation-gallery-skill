# 验收标准（Acceptance）

**原则：任一 P0 不通过 → 验收不通过，不得对客户交付 / 不得标完成。**
P1 可带缺口说明限期补；P2 为体验建议，不挡验收。

判定人：执行 AI 自检后，产品侧（GEO 产品）抽查；客户可见交付以产品签字为准。

---

## 怎么判

| 结果 | 条件 |
|------|------|
| **通过** | 全部 P0 = Pass；P1 若 Fail 须在页内或交付说明写明缺口与补抓计划 |
| **不通过** | 任一 P0 = Fail |
| **退回重做** | 编造数据、用词错误、原始标签被裁剪、口播冒充、截屏当成品等诚信/硬规则类 Fail |

抽查最低量：随机抽 ≥5 条详情卡 + 全文搜「应用」+ 检查原始与规范化标签。

```bash
# 标签规范化预览（不改文件，不代替门禁）
python scripts/normalize_hashtags.py gallery/data.json   # 输出完整规范化列表
# 用词门禁
rg -n '应用次数|应用率|次应用' gallery/index.html && echo FAIL || echo PASS
```

## P0 — 不达标即不通过

| ID | 验收项 | Pass 标准 | 怎么验 | Fail 即 |
|----|--------|-----------|--------|---------|
| A1 | 指标用词 | 页面可见文案（Hero、指标说明、Tab、图表轴/图注、详情）一律「引用次数 / 引用率 / 条均引用」等；**零**「应用次数 / 应用率 / 次应用」 | `rg` 全文 + 人眼扫 Hero/指标条 | 退回改文案 |
| A2 | 标签证据完整 | hashtags_raw 保留原始输入；hashtags 完整规范化，分析不截断；作者标签与人工主题分开 | 对照原文和 JSON | 恢复证据后重算受影响统计 |
| A3 | 数字口径 | 真实 `0` 显示 `0`；未抓到显示「暂未抓取到」或等价；**禁止**把抓取失败写成 `0` | 抽查互动为 null 的卡；对照 progress/缺口表 | 退回改数据 |
| A4 | 文字三字段 | 短标题 ≠ 发布文案 ≠ 口播文案；缺口播标缺口；**禁止**用发布文案填 `transcript` | 抽 ≥5 条：有 transcript 的与 caption 比对 | 退回清字段 |

| A6 | 五 Tab 结构 | 且仅这五且顺序固定：①视频类别 ②内容拆解 ③标题、文案与标签 ④时长与互动 ⑤全部样本 | 打开页面点一遍 | 退回改模板结构 |

```text

P0：A1__ A2__ A3__ A4__ A5__ A6__ A7__ A8__ A9__ A10__  （Pass/Fail）

```

**一票否决（直接不通过）**：编造引用次数或互动；假画面；口播冒充；「应用率」未改干净；裁剪原始标签后冒充完整统计；泄露密钥。

## 数据与证据补充门禁（P0）

- A11：同视频多链接已归并，不同视频未误并；以视频 ID 及代表性链接复核。
- A12：每条核心发现有样本、证据位置、相关问题和有效样本数；观察、解释与建议分开。
- A13：标题/文案/口播/画面按各自证据可用性统计；缺口不能用猜测补齐。
- A14：汇总与明细一致；引用回答数、覆盖问题数、原始行数不混用；跨平台及同回答重复已按口径去重。缺 answer_id 时 citation_count_status=link_occurrence 且报告有一句口径说明。
- A15：交付无旧客户结论、固定示例日期/数字、未替换占位符和内部操作说明；缺失值不得显示 undefined%、null% 等。
- A16：原始材料和过程证据仍可复核；verify/finalize 不应改写正文或删除文件。

官方模板已同步确认版；必读 approved-report-contract.md。不能因生成或打包成功就对客交付。

验收记录追加 A11 至 A16；区分打包检查、数据检查、页面检查与人工验收。

逐条记录 A1 至 A21 的 Pass/Fail/证据路径；不适用须写原因，不得留空。qa-report.md 同时列 P1 缺口及补抓计划。正文只展示必要的数据缺失说明，内部验收记录随交付文件保存，不堆在报告开头。

采集是否尽力与数据是否齐全分开判定：客观访问受限且已有尝试证据，可保留缺失的普通样本；未经尝试、遗漏可用免费渠道、精选案例证据不全均不能按“缺失正常”放行。

## v3 系统模式补充

- 时间（A17）：observed_at、attempts[].at 必须是带时区的 ISO 时刻，写 `Z` 或 `+08:00`（冒号不可省），如 `2026-09-29T04:00:35+08:00`；`+0800` 会被系统拒收。published_at 为 `YYYY-MM-DD` 或同样格式的 ISO 时间。Python 用 `datetime.now().astimezone().isoformat(timespec="seconds")`，不要用 `strftime("%z")`。
- 画面时点（A5、A18）：混剪/口播每帧必须有 timestamp_sec（≥0 且不超过 duration_sec），在抽帧时记录；须可复核（按该时点重新抽帧得到同一图片字节），无法证明时点的帧不计入 ok。图文用 page_index（从 1 起）。
- 自动转写（A4、A18）：完整覆盖整条音轨（音轨时长与视频时长相差不超过 max(2 秒, 5%)，且有有效中文口播）记 transcript status=ok，样本写 transcriptReviewStatus=pending 与 verificationEvidence（转写来源、记录文件及散列、音轨时长、段数、未人工核对原因），报告显示「自动转写，待核对」；不得记为 partial。未覆盖整轨才是 partial；无有效口播为 missing。人工逐句核对后才可写 verified / fullTextVerified=true。
- A1–A21：每条 evidence 必须是本次实际检查的结果（计数、文件、节点 ID、命令输出摘要等），不能用通用套话或统一写 passed；未通过项如实写 failed，不得先写 passed。
- 静态导出（A20、A21）：回传的 results/report.html 必须是系统导出脚本生成的静态页面——无 `<script>`、无 canvas，图片以 data:image base64 内嵌，不得引用 gallery/images 等相对路径。带脚本的本地 index.html 只用于预览和浏览器验收。
- 图文 image_text（A4、A13）：必须是图片中的文字（逐页 OCR 并校对）；页面只有发布文案时 image_text 记 missing 并写原因，不得把 caption 复制为 image_text。
- 内容形式（A13）：content_type 按每条样本自身证据判断（静态图文=image，单人对镜讲解=talking_head，剪辑拼接/字幕配乐等=montage），不得一律写 montage；无法判断时 content_type 记 missing 并写原因，不猜。
