# 分析阶段：按证据分析与按需分工

## 为什么要拆

Top10 起步，每条文案上千字时，正文总量轻松几十篇。
大批量材料应分批读取、建立证据索引，避免原文挤占分析空间。

需要独立并行分析时再派子 Agent；分工不能替代统一口径与主会话复核。

## 主会话的证据与整合职责

拉取与抓画面完成后，主会话：

1. 读 `_机器可读/top.json`，按 title/caption/transcript/visual/engagement 可用性分别汇总清单（保留平台、rank、title、script_path、account、citation_count、question_count、ranking_metric、引用问题与证据来源）。
2. 大批材料分批读取并索引；小样本可直接分析，不强制分工。
3. 按需分工或分批分析 → 复核证据 → **把洞察写入晨光陶瓷画廊五 Tab**（主交付）→ 可选落盘 `偏好分析.md`（内部归档）→ 写 README → `finalize_package.py`。

## 子 Agent 组织方式（按包模式）

**仅抖音（scope=仅抖音）：**
- 较小样本：主会话或一个子 Agent 读取本次分析维度可用的证据，按模板产出偏好洞察。
- 较大样本可拆三个子任务，主会话合并：
  - A：标题/文案特征 + 话题标签
  - B：口播结构类型 + 内容类型分布
  - C：账号类型 + 数据/时长特征 + 可复制写法
  按职责读取同一份可用证据索引；如拆样本，合并后再计算全量统计，不能把局部频率直接当全批结论。

**全部视频平台（scope=all）：**
- 按需每平台一个子 Agent 写 `平台偏好/<平台名>.md`，主会话或总论子 Agent 综合，平台样本数与口径分别注明。

## 写到哪里（统一技能）

| 产物 | 是否对客 | 说明 |
|------|----------|------|
| `gallery/index.html` 五 Tab | **主交付** | 视频类别 / 内容拆解 / 标题、文案与标签 / 时长与互动 / 全部样本；套 `assets/template.html` |
| `偏好分析.md` | 可选归档 | 结构见 [`video-preference-template.md`](video-preference-template.md) |
| 绿头 KPI HTML | **不要** | `assets/legacy/` 仅存档，禁止当客户主页 |

阶段口径 → [`stage-guidance.md`](stage-guidance.md)。

## 子 Agent 指令要点

- 只读清单内文件，禁止去读其他平台/其他批次的文案
- 严格按偏好模板结构写（标题/文案特征表、口播结构类型表、内容类型、5～7 条写法）
- 不合格样本若被误放进清单，在「样本与可信度」里剔除并说明
- 数据（时长/播放量/账号）以 `top.json` / 抓取 meta 为准，拉不到就写「未获取」/「暂未抓取到」，不要编
- 写完即停，不要收尾、不要改 top.json
- 标签分析只用完整规范化的真实标签列表（见 [`hashtags.md`](hashtags.md)）

## 质量闸门（主会话检查）

收尾前抽查：

- 画廊五 Tab 是否有实质洞察（非空壳占位）
- 若有 `偏好分析.md`：是否含「标题/文案特征」表与「口播结构类型」表；核心结论是否缺证据 → 补证据或降为假设，不以篇幅判质量
- 每项分析是否有相应证据；不得因无口播排除已核实的画面、标题或发布文案
- 是否编造了 `top.json` / engagement 里没有的播放量/点赞数
- 画廊用词是否为「引用*」且原始标签未被裁剪（再过 [`qa-checklist.md`](qa-checklist.md)）

## 每项结论的必需记录

记录 claim（发现）、kind（观察/解释假设/制作建议）、sample_ranks、evidence_refs（原文/关键帧/时间点）、related_questions、eligible_n、limitations。只有引用链接时，只能确认引用关联；实际采用哪段内容需要答案原文比对。

主类按用户需求划分，类别数量依样本确定；内容组织、证明材料、图文/口播形式分别标记。Top 样本只描述本批，不推断全平台偏好或因果。分组比较附各组数量、缺失情况，检查同账号和同模板集中度。建议须对应具体选题、所需材料与脚本动作。

报告结构与案例深度以 approved-report-contract.md 为准；禁止复用 preview 的固定结论。
